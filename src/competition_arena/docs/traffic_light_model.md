## 三、★ 一个关键认识：三个透镜始终可见

对比官方参考图可以确认：

- **亮灯**：高饱和 + 能看到内部 LED 点阵 + 有光晕
- **灭灯**：**同色但暗**、能看到透镜的棱纹纹理

也就是说，**真实红绿灯的三个透镜任何时候都看得见、各自有色，只是亮/暗不同**。

这直接推翻了我们旧模型的做法（旧模型把灭灯的灯珠**物理藏进灯箱内部**、三个透镜统一做成近黑色）。
用那种数据训 YOLO，模型会学到「彩色圆在竖排第几个位置」这种**伪特征**，
而真机上三个透镜都在、只有亮度差别 → 模型会失效。

**现在的做法**：

- 三个**暗色透镜常驻**在灯箱正面（各自真实颜色）
- 每个透镜后面挂一颗发光灯珠；亮时推到透镜前方 4 cm 露出来，灭时缩回灯箱内部
- 行程只有 4 cm，从画面看**几乎看不出灯珠伸缩**，视觉上就是「同一颗透镜亮/暗变化」

## 四、只有横排（用户确认）

官方只有**横排**一种灯具，所以两盏都用 `traffic_light_h`（竖排模型已删除）。
灯箱 64 × 14 cm，灯珠沿 +y 排开，红-黄-绿（从正面看从左到右），左右两根支架。

**模型原点在地面、水平居中**，world 里 `<pose>x y 0 yaw</pose>` 即可站稳
（旧模型原点在灯箱中心，`z` 曾给 0.55 —— 已改）。

### ⚠️ 踩过的坑：灯箱必须受重力

一开始照旧模型写了 `<gravity>false</gravity>`，结果**灯脚落在地面 z=0 上，
一有接触力、没有重力的模型就被顶飞**——实测 3 秒漂 0.08 m、23 秒漂 0.26 m，
z 一直涨。

旧模型没这问题是因为它的脚在**离地 10 cm**，整个模型是悬空道具、根本碰不到地面。
我们按官方尺寸做成"落地"，就必须老实给重力。

修法：灯箱**开重力**（三颗灯珠仍无重力，由关节托着）+ 底脚也做成碰撞体
（0.20 × 0.05 m，否则支撑多边形在前后方向只有支架的 2.5 cm 宽，容易倒）。

### ⚠️ 踩过的坑 2：启动时会"晃两下"

灯有重力后会**落地下沉**，但一开始关节的限位是 `[0.005, 0.055]`，而 SDF 的
**默认关节位置是 0，落在限位外** —— Gazebo 启动时把它弹到 0.005，这个冲击
让刚落地还没稳定的灯晃两下。

修法：**关节下限改成 0.0**（默认位置就合法，不再有启动弹跳）。
`traffic_light.py` 用的 ON/OFF = 0.050/0.010 都在 `[0, 0.055]` 内 ✓

实测修复后：`z = 0.0000`、`y = 2.0000`、**倾角 0.00°**，连续 10 秒完全不动；
灯珠伸出量也精确等于指令值（0.050 / 0.010）。

**0.34 ~ 0.48 m**，所以在 **1.0 m 外就能看到全部三颗灯** ✓

| 距离 | 相机可见高度范围 |

## 六、摆位与朝向

```
上斑马线  x [ 0.06,  0.27], y [ 1.50,  2.06]  -> 上灯放它左侧  (-0.15,  2.00)
中斑马线  x [-0.40,  0.17], y [-0.78, -0.57]  -> 下灯放它下方  (-0.12, -2.00)
```

朝向按示意图的**橙色箭头**：上灯朝 **+x**、下灯朝 **+y**。

### 上灯为什么用单支架

横排灯宽 64 cm，双支架间距 59 cm。朝 +x 摆在顶部时灯箱沿 y 铺开，靠内的那根
支架会落到 **y≈1.7 —— 正好在 60 cm 宽的车道里挡路**。单支架只占 2.5 cm，
摆在 y=2.00（车体边缘 1.94 之外）就不挡了。下灯朝 +y，支架沿车道方向排开，
不受影响，用默认双支架。

### ⚠️ 围墙高度从 0.5 m 降到了 0.30 m

上灯朝 +x 时灯箱会伸到墙外（y 到 2.32），最外侧那颗透镜在 y=2.22。
相机高 0.20 m、墙高 0.5 m 时，**视线在 y=2.076 处只有 z=0.352 m，会被墙挡住**。

降到 **0.30 m** 后视线仍高于墙顶 ✓，而且：

- 仍能挡住 0.2 m 高的车体 ✓
- 雷达（0.20 m）照常看得见 ✓
- 2D 代价地图/建图完全不受影响（都是 2D 扫描）✓

改在 `build_arena.py --wall-height`（默认值已改为 0.30）。

## 七、怎么重新生成 / 调试

```bash
python3 tools/setup_traffic_lights.py --models-only   # 只重生成模型, 不动 world
python3 tools/setup_traffic_lights.py                 # 生成模型 + 插进 world
python3 tools/setup_traffic_lights.py --show          # 看当前配置
python3 tools/setup_traffic_lights.py --remove        # 从 world 移除
```

尺寸/颜色常量都在 `tools/setup_traffic_lights.py` 顶部，改完重跑即可。
配置里每盏灯还可以给 `posts: single`（单支架）——当前两盏都用默认双支架。

### 怎么验证状态切换

⚠️ **本沙箱验证不了**：软件渲染下相机从启动起就冻住（实测连车走 1 m
画面 md5 都不变），所以画面里"哪颗灯亮"根本看不出来。

**在你的机器上**（有 GPU）跑：

```bash
roslaunch competition_robot robot_gazebo.launch
roslaunch competition_arena traffic_light.launch        # 起切换节点
python3 tools/check_traffic_light.py --save /tmp/red.png      # 看相机里的颜色
```

**或者用位姿验证**（不依赖渲染，任何机器都能跑）：

```bash
python3 tools/verify_traffic_light.py    # 查三颗灯珠沿灯箱正面方向的伸出量
```

实测结果 6/6 全部正确（设红→红伸出 0.075 m，另两颗 0.039~0.044 m）。
